## 4. 起きたこと（次も気を付ける）

- **#57 の本番配信が 1 回失敗**: Google の Apps Script API が `UNAVAILABLE`（運営用 GAS のコードを送る最初の手順。版の作成・デプロイの差し替えの前）。本番は前の版のまま動いていた。利用者に確認してから、`mcp__github__actions_run_trigger`（`rerun_failed_jobs`、run 41802718876）で失敗したジョブを再実行し、成功（30→31・23→24）。再実行の前に main が進んでいないこと（古いコミットで上書きしない確認に引っかからない）を確かめた。
- **`;` でつないだコマンドで、cherry-pick の衝突の後に worktree とローカルブランチの削除まで進んだ**（コミットは cherry-pick の途中の状態が持っていたので失われなかった）。片づけは成功を確かめてから別のコマンドで。
- 試験計画（`tournament-poc/docs/test-plan.md`）の表に、同じ行の後へ別々の PR が行を足すと cherry-pick で衝突する（両方の行を残して解消）。
- `gh api` で CI を読んでいたのは環境の決まりに反していた（読み取りだけ。MCP に切り替えた）。
- マージのとき `expectedHeadSha` を 2 回打ち間違えた（GitHub が拒否したので影響なし）。必ず `git rev-parse HEAD` の出力を写す。

### 規則の判断が要る（着手の前に利用者に方針を聞く）

- **10／期制照合　部分反映の定員検査**: 4人の部を5人にする単独移動は合意した定員規則で拒否、同時入替と欠員補充は成立。拒否時に行・ログ不変。／最低人数と既存の手動編集を回帰。設定・所属を保全してからrevert。

- **19／不戦勝後の訂正　操作不能を解消**: 棄権からの復帰、前試合訂正、下流結果の有無、再抽選を比較。開始済み試合を保護。／勝ち抜き表に影響。revert前に対象対戦表を保全。棄権後の表生成・再抽選の修正は再現箇所ごとに別PR。
