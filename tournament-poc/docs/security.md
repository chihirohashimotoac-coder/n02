# セキュリティ設計と公開前チェックリスト

## 1. 前提（誰が何をできるか）

| 立場 | 確かめ方 | できること |
| --- | --- | --- |
| 閲覧者 | なし（ログイン不要） | 公開された大会の閲覧のみ |
| 主催者 | Google でログイン（大会に紐付いた Google アカウント。v0.9 から ID トークンの `sub` で判定） | 大会の作成（1 人 1 時間に 5 件・全体で 1 時間 10 件・合計 200 件まで）、自分が作った大会の運営（管理パスワードの設定・変更を含む） |
| 店舗スタッフ | 大会ごとの管理パスワード（主催者が設定） | その大会だけの運営（選手・グループ・結果・公開）。管理パスワードの変更と大会の作成はできない |
| 管理者（あなた） | 管理者の鍵（スクリプト プロパティ `ADMIN_KEY`、24 文字以上） | 初期設定・全大会の管理・閲覧ページの既定表示・大会の主催者の付け替え |

v0.5.0 で「運営用 URL（鍵入りの URL）」と「作成コード」を廃止しました。運営画面の URL（`/admin/#e=大会ID`）には秘密の情報を含めず、
URL だけを知っていても開けません。

Google ログインの確認方法: 運営画面（GitHub Pages）で Google Identity Services のボタンから ID トークンを受け取り、運営用 Apps Script が
Google の tokeninfo エンドポイントに問い合わせて、宛先（`aud` = スクリプト プロパティ `GOOGLE_CLIENT_ID`）・発行元・有効期限・メール確認済み・`sub` を確かめます。
v0.9.0 から、主催者・共同主催者は `sub`（Google アカウントごとに不変）で識別し、メールアドレスの一致だけでは権限を与えません。
新しく作る大会は、作った人の `sub` がその場で主催者になります（承認は不要）。既存の大会（v0.8.0 以前）・管理者が付け替えた大会・共同主催者の招待は本人のログインで紐付け、
Google が持ち主を保証しないアドレス（`@gmail.com` でも Google Workspace（`hd`）でもない）の場合だけ承認が必要です（共同主催者は主催者が、既存の大会の主催者は管理者が承認。[v0.9-identity.md](v0.9-identity.md)）。
Google は tokeninfo を「開発・デバッグ用」と位置づけ、本番では検証ライブラリを推奨していますが、Apps Script ではそのライブラリを使えないため、
ログインの瞬間だけ tokeninfo を使い、以後はサーバーが発行するセッションで確かめます
（[Verify the Google ID token](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)）。

## 2. 脅威と対策

| 想定 | 対策 | 確認方法 |
| --- | --- | --- |
| 閲覧ページや運営画面・運営用 Web アプリの URL を知った人が書き込もうとする | 運営用 API は、操作のたびにセッション（または管理者の鍵）をサーバー側で検証。ログインしていなければ初期表示とログイン以外は拒否 | `security.test.mjs`・`e2e/security.spec.mjs`（模擬） |
| 偽の Google ログイン | ID トークンを tokeninfo で確かめ、`aud`（自分のクライアント ID）・`iss`・`exp`・`email_verified`・`sub` を照合。署名違い・期限切れ・別アプリ向け・発行元違い・メール未確認・`sub` なし・形式違いはすべて拒否。tokeninfo の混雑（429・5xx）は「接続できない」と表示。通信の例外の文面（URL にトークンを含みうる）はログに出さない | 自動テスト（模擬 tokeninfo。`identity.test.mjs`） |
| メールアドレスの再割り当て・なりすまし・変更（v0.9.0） | 権限は `sub` で判定。既存の大会・招待の紐付けは、Google が持ち主を保証するアドレスで、既存の紐付けと矛盾しないときだけ自動。それ以外は確認待ち（権限なし）にして主催者・管理者が承認。招待（共同主催者の追加）・管理者の付け替えは、それだけでは権限を与えない。v0.8 形式のセッションは無効 | 自動テスト（`identity.test.mjs`）・画面テスト（`e2e/identity.spec.mjs`） |
| 主催者が、他人の大会を操作しようとする | 操作対象を eventId / matchId / playerId / groupId / stageId のどれで指定しても、その大会の主催者・共同主催者の `sub` とログイン中のアカウントを照合。違えば「見つからない」と同じ応答（他の大会の存在を知らせない） | 自動テスト（15 種類の操作で他の大会を指定） |
| 管理パスワードの総当たり | 同じ大会で 10 回間違えると 10 分間受け付けない。存在しない大会・形式違いも同じエラー。パスワードは 8〜64 文字 | 自動テスト |
| 管理パスワードの漏えい | 主催者がいつでも変更・解除でき、変えるとそのパスワードで作ったセッションはすぐに使えなくなる。シートにはソルト付き SHA-256 だけを保存し、履歴・API の応答にはハッシュもソルトも含めない。比較は途中で打ち切らない方法 | 自動テスト |
| セッションの盗用 | セッションは 244 ビット相当の乱数。サーバーのキャッシュにだけハッシュ化したキーで置き、6 時間で切れる。ログアウトで無効化（v0.9.0: 先に端末から消し、サーバーでの無効化を確かめられたときだけ成功と表示。失敗・時間切れは警告と再試行。別タブにもすぐ反映）。ブラウザ側は運営ページのオリジンの localStorage に保存（CSP でスクリプトを限定）。**残るリスク**: 同じオリジン（同じ GitHub アカウントの他の Pages を含む）で動くスクリプト・XSS からは読める | 自動テスト・画面テスト |
| ログインの大量呼び出し（外部通信の割り当ての消費） | 形式違いのトークンは問い合わせ前に拒否。Google への問い合わせは全体で 1 分あたり 30 回まで | 自動テスト |
| 大会の誤削除・不正な削除 | 削除と保存（エクスポート）は大会を作った本人と管理者だけ（スタッフ・他の主催者は不可）。大会名の入力が一致しないと削除しない。版番号（rev）が古ければ拒否。保存ファイルに管理パスワードのハッシュ・ソルトを含めない。削除したことは履歴に残す | 自動テスト |
| 匿名での大量作成（スパム） | 作成は Google ログイン必須。1 人 1 時間 5 件・全体 1 時間 10 件・合計 200 件の上限（管理者は対象外） | 自動テスト |
| 閲覧者用から書き込み・初期化 | 閲覧者用は別プロジェクト。書き込み処理がコードに存在せず、スコープも `spreadsheets.readonly` のみ | 自動テスト |
| 同時更新・二重送信 | 書き込みはスクリプトロックで直列化。版番号（rev）が古ければ拒否。`requestId` で二重送信を無視（大会作成の再送では同じ大会を返す） | 自動テスト |
| 不正な入力 | すべてサーバー側で検証してから書き込む（型・範囲・長さ・参照先・Best of の成立条件） | 自動テスト |
| スプレッドシートの数式注入 | 先頭が `= + - @` の文字列を拒否。公開データの分割 JSON には先頭に `~` を付けて保存 | 自動テスト |
| XSS | 画面はすべて `textContent` で表示。GitHub Pages のページは CSP でスクリプトを同じサイトのファイル（運営ページは Google のログイン用ライブラリも）に、通信先を Apps Script（と Google のログイン）に限定 | 自動テスト・画面テスト |
| 個人情報・内部情報の公開 | 閲覧者に渡すのは公開用 JSON のみ（返却キーの一覧をテストで固定）。主催者のメールアドレスは本人と管理者にだけ返し、スタッフ・閲覧者には出さない。`sub` はどの応答・履歴・保存ファイルにも出さない（承認の画面には sub のハッシュの先頭 12 文字だけ）。保存先 ID は管理者にだけ返す | 自動テスト |
| 内部エラーの漏えい | 固定文言のエラーのみ返し、詳細はサーバーログへ | 自動テスト |
| 既存の Google ファイルの誤上書き | 保存先はスクリプト プロパティで指定した 1 ファイルのみ。管理対象外のデータがあれば初期化を中止 | 自動テスト |
| 運営用アプリの権限の悪用 | スコープはスプレッドシートと外部通信（`script.external_request`）のみ。外部通信のコードは tokeninfo への 1 か所だけ（メール・Drive 操作のコードもなし） | 自動テスト（マニフェストとコード） |
| ポータルの公開一覧から非公開の大会が漏れる（v0.7.0） | 一覧は閲覧者用 Web アプリが PublicSnapshots（公開中の大会の公開用 JSON）だけから作る。非公開にすると運営用が行を消すので、一覧の作り方に関係なく載らない。返すのは要約（大会名・開催日・状態・形式・人数・試合数・進捗・段階名・更新時刻）だけ | 自動テスト（`portal-api.test.mjs`） |
| 他人の大会を「作成した大会」に混ぜる・他人の非公開大会を知る（v0.7.0） | `myEvents` は Google ログインのセッション（サーバーで確かめた `sub`）と各大会に紐付いた `sub` だけで絞り込み、送られたメールアドレス・大会 ID は使わない。管理パスワードのセッション・管理者の鍵・未ログインでは返さない | 自動テスト |
| ポータルから運営画面への移動でのセッションの受け渡し（v0.7.0） | ポータルと運営画面は同じオリジン（GitHub Pages）で、同じ localStorage のログインを使う。URL にセッション・パスワードを載せない（運営画面へは大会 ID だけ）。運営画面に入れるかは運営画面がサーバーに毎回確かめる（ポータルの判断は案内のみ） | 自動テスト（`security.test.mjs`）・画面テスト（`portal.spec.mjs`） |
| 管理パスワードの総当たり（並列送信で回数制限をすり抜ける）（v0.7.1） | 間違いの回数の確認から書き戻しまでをスクリプトロックの中で行う。ロックを取れなければ照合せず BUSY | 自動テスト（`portal-api.test.mjs`） |
| 非公開にした大会が予備キャッシュから返る（v0.7.1） | 閲覧者用は予備（stale）を持つ大会 ID の一覧を保存し、読み直しのたびに公開をやめた大会の予備を消す | 自動テスト（`viewer-api.test.mjs`） |
| 認証情報の埋め込み | ソースに ID・鍵・メールアドレスを含めない（スクリプト プロパティ・`config.js`）。OAuth クライアント ID は公開前提の値で、クライアント シークレットは使わない | 自動テスト |

## 3. スクリプト プロパティ（運営用プロジェクト）

| 名前 | 必須 | 内容 |
| --- | --- | --- |
| `SPREADSHEET_ID` | ○ | データ保存用スプレッドシートの ID |
| `ADMIN_KEY` | ○ | 管理者の鍵。**24 文字以上の推測できない文字列**（パスワード管理ソフトで生成するなど）。他人に教えない |
| `GOOGLE_CLIENT_ID` | ○ | Google Cloud で作った OAuth クライアント ID（`…apps.googleusercontent.com`）。運営画面の `admin/config.js` の `googleClientId` と同じ値 |
| `VIEWER_URL` | 任意 | 閲覧ページの URL（運営画面から設定） |
| `CREATE_CODE` | 不要 | v0.4 までの作成コード。v0.5.0 では使わないので、残っていれば削除して構いません |

## 4. 公開前チェックリスト

- [ ] スプレッドシートの共有設定が「制限付き」で、共有相手がいない
- [ ] 運営用プロジェクトのスクリプト プロパティ `ADMIN_KEY` が 24 文字以上で、推測できない
- [ ] `GOOGLE_CLIENT_ID` と `admin/config.js` の `googleClientId` が同じ値で、OAuth クライアントの「承認済みの JavaScript 生成元」が GitHub Pages のオリジン（`https://<ユーザー名>.github.io`）だけ
- [ ] 運営用デプロイ: 実行「自分」、アクセス「全員」。`appsscript.json` のスコープがスプレッドシートと外部通信のみ
- [ ] 閲覧者用デプロイ: 実行「自分」、アクセス「全員」。スコープが `spreadsheets.readonly` のみ
- [ ] GitHub Pages の `config.js`・`admin/config.js` に書いたのが Web アプリの URL とクライアント ID だけ（鍵・パスワードを書いていない）
- [ ] ログインしていない運営画面（`/admin/` や `/admin/#e=大会ID`）では、ログイン・管理パスワードの画面しか出ない
- [ ] 他人の Google アカウントでログインすると、自分の大会が一覧に出ず、URL を開いても「権限がありません」になる
- [ ] 管理者の大会一覧に「主催者の紐付け待ち」「主催者の承認待ち」が残っていない（残っていれば本人に確かめてから承認する）
- [ ] 管理パスワードを変えると、スタッフの画面がログインし直しになる
- [ ] 公開している大会が意図したものだけ（管理者画面の大会一覧で確認）
- [ ] 選手名に本名を使う場合は、本人の同意があること
- [ ] Apps Script プロジェクトの共有相手がいない（編集者はコード・実行ログ・スクリプト プロパティを見られる）
