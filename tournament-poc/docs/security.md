# セキュリティ設計と公開前チェックリスト

## 1. 前提（誰が何をできるか）

| 立場 | 確かめ方 | できること |
| --- | --- | --- |
| 閲覧者 | なし（ログイン不要） | 公開された大会の閲覧のみ |
| 主催者 | 大会ごとの運営用 URL（`/admin/#e=大会ID&k=鍵`）の鍵 | その大会だけの運営（選手・グループ・結果・公開・運営用 URL の再発行） |
| 大会を作る人 | 作成コード（スクリプト プロパティ `CREATE_CODE`。未設定なら誰でも） | 大会の作成（1 時間に 10 件まで・全体で 200 件まで） |
| 管理者（あなた） | 管理者の鍵（スクリプト プロパティ `ADMIN_KEY`、24 文字以上） | 初期設定・全大会の管理・閲覧ページの既定表示・運営用 URL の再発行 |

**Google ログインは使いません。** 主催者の確認は「運営用 URL を持っているか」だけです。URL が他人に渡れば、その人も運営できます。
大会単位で被害を限定し、気づいたら再発行で古い URL を無効にする、という考え方です。

## 2. 脅威と対策

| 想定 | 対策 | 確認方法 |
| --- | --- | --- |
| 閲覧ページや運営用 Web アプリの URL を知った人が書き込もうとする | 運営用 API は、操作のたびに大会の鍵または管理者の鍵をサーバー側で検証。鍵がなければ大会の作成（作成コード・上限あり）と初期表示以外は拒否 | `security.test.mjs`・`e2e/security.spec.mjs`（模擬） |
| ある大会の主催者が、別の大会を操作しようとする | 操作対象を eventId / matchId / playerId / groupId のどれで指定しても、その大会の event_id を引いて鍵の大会と照合。違えば「見つからない」と同じ応答（他の大会の存在を知らせない）。グループと大会の組み合わせも確認 | 自動テスト（12 種類の操作で他の大会を指定） |
| 鍵の総当たり・推測 | 鍵は UUID v4 2 つ分の乱数（244 ビット相当）。形式違い・違う鍵・存在しない大会を同じエラーで拒否 | 自動テスト |
| シートや履歴からの鍵の漏えい | シートには SHA-256 のハッシュだけを保存。履歴・API の応答にもハッシュを含めない。比較は途中で打ち切らない方法 | 自動テスト（シート全体に鍵の文字列がないこと） |
| 運営用 URL の漏えい | 主催者・管理者が再発行でき、古い URL はすぐに無効。URL の鍵は `#` 以降にあり、GitHub Pages のサーバーにもリンク先への Referer にも送られない（`referrer: no-referrer` も指定） | 自動テスト・画面テスト |
| 匿名での大量作成（スパム） | 作成コード（任意）、1 時間あたり 10 件・全体 200 件の上限（管理者は対象外） | 自動テスト |
| 閲覧者用から書き込み・初期化 | 閲覧者用は別プロジェクト。書き込み処理がコードに存在せず、スコープも `spreadsheets.readonly` のみ | 自動テスト |
| 同時更新・二重送信 | 書き込みはスクリプトロックで直列化。版番号（rev）が古ければ拒否。`requestId` で二重送信を無視（大会作成の再送では同じ鍵を返す） | 自動テスト |
| 不正な入力 | すべてサーバー側で検証してから書き込む（型・範囲・長さ・参照先・Best of の成立条件） | 自動テスト |
| スプレッドシートの数式注入 | 先頭が `= + - @` の文字列を拒否。公開データの分割 JSON には先頭に `~` を付けて保存 | 自動テスト |
| XSS | 画面はすべて `textContent` で表示。GitHub Pages のページは CSP でスクリプトを同じサイトのファイルに、通信先を Apps Script に限定 | 自動テスト・画面テスト |
| 個人情報・内部情報の公開 | 閲覧者に渡すのは公開用 JSON のみ（返却キーの一覧をテストで固定）。保存先 ID は管理者にだけ返す | 自動テスト |
| 内部エラーの漏えい | 固定文言のエラーのみ返し、詳細はサーバーログへ | 自動テスト |
| 既存の Google ファイルの誤上書き | 保存先はスクリプト プロパティで指定した 1 ファイルのみ。管理対象外のデータがあれば初期化を中止 | 自動テスト |
| 運営用アプリの権限の悪用 | スコープはスプレッドシートのみ（外部通信・メール・Drive 操作のコードもなし） | 自動テスト（マニフェストとコード） |
| 認証情報の埋め込み | ソースに ID・鍵・メールアドレスを含めない（スクリプト プロパティ） | 自動テスト |

## 3. スクリプト プロパティ（運営用プロジェクト）

| 名前 | 必須 | 内容 |
| --- | --- | --- |
| `SPREADSHEET_ID` | ○ | データ保存用スプレッドシートの ID |
| `ADMIN_KEY` | ○ | 管理者の鍵。**24 文字以上の推測できない文字列**（パスワード管理ソフトで生成するなど）。他人に教えない |
| `CREATE_CODE` | 推奨 | 作成コード。大会を作ってよい人にだけ教える。未設定なら誰でも作成可能 |
| `VIEWER_URL` | 任意 | 閲覧ページの URL（運営画面から設定） |

## 4. 公開前チェックリスト

- [ ] スプレッドシートの共有設定が「制限付き」で、共有相手がいない
- [ ] 運営用プロジェクトのスクリプト プロパティ `ADMIN_KEY` が 24 文字以上で、推測できない
- [ ] `CREATE_CODE` を設定した（誰でも作れる状態にする場合は、その判断を記録）
- [ ] 運営用デプロイ: 実行「自分」、アクセス「全員」。`appsscript.json` のスコープがスプレッドシートのみ
- [ ] 閲覧者用デプロイ: 実行「自分」、アクセス「全員」。スコープが `spreadsheets.readonly` のみ
- [ ] GitHub Pages の `config.js`・`admin/config.js` に書いたのが Web アプリの URL だけ（鍵・ID を書いていない）
- [ ] 鍵のない運営画面（`/admin/`）では、大会の作成画面しか出ない
- [ ] 運営用 URL の鍵を 1 文字変えて開くと「使えません」になる
- [ ] 公開している大会が意図したものだけ（管理者画面の大会一覧で確認）
- [ ] 選手名に本名を使う場合は、本人の同意があること
- [ ] Apps Script プロジェクトの共有相手がいない（編集者はコード・実行ログ・スクリプト プロパティを見られる）
