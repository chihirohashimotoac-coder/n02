## 設計の要点

### 保存（03_storage）
- ctx のテーブルはメモリ上で変更し、`commitContext_` で一括書込（更新 → 削除 → 追加の順。行番号がずれない）。
  検証エラーは書込前に起きるので、失敗した操作は何も書かない。
- 書込直前に `WRITE_JOURNAL`（スクリプト プロパティ）を置き、成功後に消す。残っていれば次の操作で
  「前回の保存が途中で止まった可能性」を履歴に記録し、同じ requestId の再送は `PARTIAL_WRITE` で止める。
- 公開データは書込前に組み立てて大きさを確かめる（上限超過は保存しない）。
- スキーマ v2: Events.config_json / Players.affiliation, rating, seed, meta_json / Groups.meta_json /
  Entries.start_round, meta_json / Matches.result_type, result_note, schedule_json, bracket_side, meta_json / 新シート Collaborators。
  読み込みは v2 の列がなくても空として読む（移行前の短い時間に旧画面が読めるように）。書込系は `MIGRATION_REQUIRED`。
- 移行 `migrateStorage`（管理者の鍵のみ）: バックアップ（同じスプレッドシート内に `bak-<版>-<シート>` を複製）→ 列・シート追加 →
  件数照合 → `SCHEMA_VERSION=2`。何度呼んでも安全。公開閲覧からは起動しない。

### 形式（shared/formats.js が唯一の定義）
順: robin_ko / elimination / robin_ab / double_elimination / robin / league / league_playoff / multi_robin_ko / series_playoff / swiss。
段階の種類: round_robin・league・single_elimination（既存）＋ double_elimination・swiss・series。

### ブラケットの汎用エンジン（04_domain）
節点 = { 出所 2 つ（選手 / ある試合の勝者 / 敗者 / なし）}。出所の有無だけで「試合 / 素通り（不戦） / 空」を静的に決める。
SE（途中回戦シード・Bye）、DE（勝者側・敗者側・GF・リセット）、シリーズの各節 KO に使う。
